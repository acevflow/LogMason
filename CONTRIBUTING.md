# Contributing to LogMason

Thank you for your interest in contributing to LogMason.

LogMason is an open-source Python logging library under development. Contributions that improve its reliability, maintainability, documentation, and usability are welcome.

## Before Contributing

Before starting work on a substantial change:

1. Check the existing GitHub issues and pull requests for related work.
2. Open an issue to discuss significant changes, new features, or architectural proposals before implementing them.
3. For small fixes, such as correcting a typo, a discussion may not be necessary.

This helps avoid duplicated effort and ensures that proposed changes align with the project's direction.

## Development Workflow

1. Fork the repository if you do not have write access.
2. Clone your fork to your local machine.
3. Create a branch for your change.
4. Implement the change, keeping it focused and easy to review.
5. Run the relevant checks available in the repository.
6. Commit your changes with a clear, descriptive message.
7. Open a pull request against the upstream repository.

Use descriptive branch names, such as `fix/issue-description` or `feature/feature-description`.

## Code Guidelines

Contributions should follow these principles:

- Write clear, readable, and maintainable Python code.
- Follow the conventions already established in the codebase.
- Prefer small, focused changes over unrelated modifications.
- Avoid introducing unnecessary dependencies.
- Document public APIs and non-obvious behavior where appropriate.
- Consider error handling, compatibility, and potential regressions.
- Do not include unrelated formatting changes.

Specific formatting, linting, typing, and testing requirements may be introduced as the project establishes its development tooling.

## Testing

When contributing code:

- Add or update tests when a suitable test suite is available.
- Run relevant tests and checks before submitting a pull request.
- Include any important manual verification steps in the pull request description.
- Clearly disclose checks that could not be performed.

Do not claim that a change has been tested if it has not been tested.

## Documentation

Update the relevant documentation when a change affects public APIs, configuration, behavior, installation, or usage.

Documentation should accurately describe implemented functionality and known limitations. Do not document planned features as if they were already available.

## Commit Guidelines

Write concise, descriptive commit messages that explain the purpose of each change.

Keep commits focused where practical. Follow any additional commit conventions established by the repository.

## Pull Requests

A pull request should include:

- A clear summary of the change.
- The motivation and relevant issue number, if applicable.
- A description of important implementation decisions.
- Tests or checks performed and their results.
- Documentation updates, where applicable.
- Known limitations or follow-up work.

Keep pull requests focused and be prepared to address constructive review feedback.

Submitting a pull request does not guarantee acceptance. Maintainers may request changes, defer a proposal, or decline contributions that do not align with the project's goals.

## Reporting Bugs and Requesting Features

Use GitHub issues to report bugs and suggest improvements when the relevant issue categories are available.

Include enough context to understand the problem or proposal. For bug reports, provide reproduction steps, expected behavior, actual behavior, and relevant environment information where possible.

Do not publish security vulnerabilities in public issues. Follow the instructions in [SECURITY.md](SECURITY.md) instead.

## Code of Conduct

Participation in the project is subject to the rules described in [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Questions

For questions about contributing, use the repository's available GitHub discussion or issue channels, where appropriate.

Additional contribution guidelines may be introduced as the project develops.
