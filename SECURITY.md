# Security Policy

## Supported Versions

LogMason is currently under development. A formal security support policy for released versions has not yet been established.

Security fixes and supported versions will be documented here as the project matures.

## Reporting a Vulnerability

**Please do not disclose suspected security vulnerabilities in public GitHub issues.**

Instead, report them privately to the project maintainers.

If GitHub's private vulnerability reporting feature is enabled for this repository, use it to submit your report. Otherwise, contact a maintainer through an appropriate private contact method listed in their GitHub profile.

When reporting a vulnerability, include, where possible:

- A description of the potential vulnerability.
- The affected version, commit, or component.
- The potential impact.
- Reproduction steps or a proof of concept, if available.
- Any suggested mitigation.

Please avoid including secrets, credentials, or sensitive personal information in your report unless strictly necessary.

## Response Process

The maintainers will review reports as their availability permits. They may request additional information to assess the issue and determine an appropriate fix.

Response times and a formal disclosure process have not yet been established.

Please allow the maintainers a reasonable opportunity to investigate and address a vulnerability before making it public.

## Scope

This policy covers security vulnerabilities in the LogMason project and its maintained code.

Issues involving third-party dependencies should generally be reported to the relevant maintainers as well.

## Policy Updates

This document may be updated as LogMason establishes its release process and security practices.
